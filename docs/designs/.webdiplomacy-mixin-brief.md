# Brief v2: webDiplomacy optimizer-seed mixin

Doc type: design doc · 2026-10-09 (PDT) · Status: revised after review (James's comments, plus findings from the
webdiplomacy_lab in personal_labs). Reader: James. **Concise; readability over completeness.** One section per thing
added. This revision replaces v1. Key changes are listed in "What changed since v1" near the top.

## Problem

`optimizer/mixin/` (PR #8) is the optimizer-seed `games/_template` with only the identity filled in. An agent
onboarding from the public template `Metta-AI/webdip-optimizer` sees all five required bindings as gaps, and finds no
game docs, no reference policy and no build tool. Core seed skills resolve every game-specific fact through the lab's
`MIXIN.md` and the bindings [src: optimizer-seed `games/_template/MIXIN.md`]. Goal: fill the lab completely, using
what the existing webdiplomacy_lab (in `~/coding/personal_labs/personal_labs_webdip/webdiplomacy_lab/`, "the lab"
below) has already learned, so the loop works for webDiplomacy in any environment.

## What changed since v1
- **Reference policy:** Herald is replaced by an adaptation of the lab's Castlereagh: Kissinger search as the core,
  plus Castlereagh's press harness as an optional, modular layer. Press is off by default for now.
- **Evaluation opponents follow the current field.** A campaign keeps one opponent set so its results stay comparable,
  and the set is refreshed when the field changes.
- **Measured priors** replace "N floors unknown". Paired seating is the default A/B design. |z| < 2 is no result.
- **Docs:** AGENTS.md becomes the lab's operating manual. Game facts move to `docs/game.md`. New `docs/protocol.md` and
  `docs/platform.md`. Pinning applies to coworld-provided docs only; users can write their own long references.
- **Tools:** port the lab's instruments instead of writing new ones from scratch. Includes local-run wrappers and the
  local LLM sidecar emulator.
- **Diagnosis** starts from failures the lab actually observed.
- **Coworld change, separate PR:** optional `countries` pinning in the episode config and `WEBDIP_END_YEAR` for bots.
  (Being implemented now, PR in coworld-webdiplomacy.)

## Evidence from the lab (headline)
- **Castlereagh's strength is Kissinger's search.** In about 100 hosted press games, the press bot scored 0.124–0.126
  per seat, while silent Kissinger (same search, no LLM) scored 0.172–0.176 in the same field [src: lab
  WORKING_CONTEXT.md; feedback file §headline]. Parity is 1/7 = 0.143. No press change has a verdict at n = 16 per
  arm. Trending positive: the map-connectivity briefing (v7, 0.163) and stronger models (deepseek 0.192, gpt-6-luna
  0.175). Liar marks (v8, 0.078) look harmful.
- **Why keep the press harness anyway (James's call):** policies with press do better than no-press bots in real
  Diplomacy, so press should help eventually, and Castlereagh is a built-out starting point. Making press-on stronger
  than press-off before release is a major goal.
- Measured gains in search: the "competent opponent" test (judge opponents by whether their orders are sensible) was
  +0.106 (z 2.25); the level-1 opponent model (Kissinger) +0.135 (z 2.4). Level 0, level 2 and mixes lost 0.10–0.14
  [src: lab best_practices.md].
- Refuted: learned evaluation (exploited: 0.64 → 0.33), rollouts (−0.13), restarts, three-unit attacks, more opponent
  samples, build search, risk aversion, evolution (53 generations, never beat the champion). Rule: more search over
  the same evaluation hurts.

## Cross-cutting decisions
1. **Summaries in the lab; coworld-provided references pinned.** The lab carries enough that a newcomer understands
   the game without leaving it. The long references this repo provides (bot API, replay schema, protocol) are linked
   at a pinned commit, so they match the coworld version. Users are free to write their own long references in the
   lab; nothing restricts that.
2. **Country first, against same-batch field par.** Countries are a seeded shuffle per episode [src:
   adapter/episode.py:83-85]. Field average by power over 1,238 lab seats: France 0.290, Turkey 0.191, Italy 0.119,
   Germany 0.114, Russia 0.114, Austria 0.099, England 0.090 [src: feedback file §2]. France is about 3× England. The
   metric is a policy's score minus the field average for the same power in the same batch of games.
3. **Tools read files, so they work for local and hosted runs alike.** A local `coworld run-episode` writes the same
   `results.json`, replay and logs as a hosted episode. The analysis tools are standard-library Python. Tools that
   *run* games locally need Docker (local machines, Claude Code cloud; Codex cloud unknown). Local results are for
   debugging only: v4 won the local tournament (+0.093) and then scored below par hosted [src: transcripts be2ac73c,
   2026-10-07].
4. **Both leagues.** "webDiplomacy" (`league_1bccc63d-cd0a-47d7-92d7-e762797b5f1c`, `classic-press`) and
   "webDiplomacy Gunboat" (`league_428e91e5-ee25-4f9c-be5e-a4fc4f993f17`, `classic-gunboat`).

## Sections (one per thing added)

### 1. Lab manual (`AGENTS.md`) and manifest (`MIXIN.md`)
- `AGENTS.md` becomes the lab's operating manual: how to use the lab, links to every knowledge source (docs, the five
  bindings, tools, reference policy, META.md), the loop table, and the gotchas an agent must not miss. Game facts
  (rules, scoring, structures) move to `docs/game.md`.
- Gotchas to carry: upstream returns HTTP 200 when it silently drops invalid orders, so diff saved orders every phase
  [src: AGENTS.md:78-79; players/api.py:104]; scores are in slot order; the replay's final `Finished` history entry
  shows center ownership from before the last autumn, so take final centers from `results.json` [src: feedback §2];
  hosted seat logs sometimes arrive as a Python `b'...'` bytes literal; use a private `HOME` per session because other
  sessions switch the identity in a shared `~/.softmax/credentials.yaml` (private requests then 404); use one image tag
  per experiment, because rebuilding a tag mid-run switches code.
- `MIXIN.md`: league IDs, the five binding rows with real summaries, meta-recon support rows, and "what else" rows.

### 2. Game docs (`docs/`)
- `game.md`: rules a bot author needs (units, phases Diplomacy/Retreats/Builds, orders, supply centers, the 18-center
  solo: one power owns 18 centers and wins outright, scoring 1 while everyone else scores 0), scoring (default
  sum_of_squares = SC² / total surviving SC²; cancelled = 1/7 each [src: docs/protocol.md:86-91]), `results.json`
  fields [src: docs/protocol.md:93-106], structures (slot vs country, turn 0 = Spring 1901, year = 1901 + turn // 2,
  upstream calls movement `Diplomacy`), variants, leagues, timing.
- Variants [src: coworld_manifest_template.json:203-235]: classic-press (Regular, 4-min movement, 1-min
  retreats/builds, through 1908); classic-gunboat (none, 1/1, through 1910); classic-press-short (Regular, 3/1, through
  1904); classic-live-human (Regular, 7/2, through 1904).
- Timing: hosted full classic-press games took 60–100 minutes in the lab (about 61 by one measurement, 80–100 by
  another). The episode budget cap is 5,910 s, about 98 minutes [src: adapter/config.py:20]. Local gunboat games with
  Ready-marking bots take 40–45 s; local search games about 4.5 minutes.
- `protocol.md` (new): the bot contract and communication in brief: the launcher, `WEBDIP_*` environment
  [src: docs/protocol.md:42, :206], the HTTP API, press and votes, the LLM sidecar, private-press artifacts. Links to
  this repo's full docs at the pinned commit.
- `platform.md` (new): hosted specifics: XP requests and costs, artifact downloads (rate limits; re-run to resume), a
  parent request rolls up to `failed` when one child fails, LLM sidecar per-model quirks (it forces
  `require_parameters`; gpt-6-luna and claude-haiku-5.5 reject temperature; gemini-3.5-flash-lite rejects reasoning
  off; deepseek, qwen and minimax reason past a 2,000-token cap and return nothing), credentials hygiene.
- `strategy.md`: a general Diplomacy primer labeled "not yet verified against this field", plus the measured field
  facts (power par; the best press seat in the lab's field was a liar soul on gpt-6-luna, 0.195–0.208). The live field
  picture goes in `META.md`, filled by `meta-recon`.

### 3. `ab` binding
- Metric: score minus same-batch field par for the same power (per-power), then pooled. Also final centers, survival,
  solo rate.
- Default design: **paired seating**: both policies in the same games. Needs 2–3× fewer games than separate arms
  [src: feedback §2]. Use separate arms only when pairing is impossible.
- Statistics: |z| < 2 is no result. Three +0.08 leads at z ≈ 1.4 vanished on replication [src: lab best_practices.md].
- Priors for sample size: per-seat SD about 0.12–0.18; about 150 episodes per arm to resolve a 0.04 difference; at 16
  per arm SE is 0.02–0.03, which only catches effects of about 0.08 or more. Recompute after the first batch.
- Taint (drop or flag before means): cancelled games; a nonzero `rejected` count in our decision log; any exception in
  our seat log; missing artifacts (report coverage, never impute); a failing LLM seat (every call fails and the seat
  silently plays its floor; check per-seat `llm_call` statuses); mixing opponent sets across a field change.
- Tools: `paired.py` and `compare.py` (ported).

### 4. `survey` binding
- Overview per policy × power: games, score vs par, final centers, survival, solo rate; outcome and reason mix.
- Worth opening: our power eliminated early; an opponent solo; our best and worst game per power; a large center swing
  within one year (a stab or collapse); failing LLM seats.
- Tool: `wd_summary.py` (port of `wd.py metrics`/`seats`; `seats` gives one JSON row per seat with the supply-center
  trajectory by year).

### 5. `replay-inspection` binding (James: big later improvement; fine for now)
- Replay: gzip JSON array of public frames: `variant`, `game`, `status`, `history`, `messages`, `lifecycle`,
  `episode.seed`, optional `map` PNG, `ending` [src: docs/replay.md:15-40]. Our own artifacts: player log and the
  private-press ZIP [src: docs/protocol.md:210-225]. Shared clock: (turn, phase).
- The reference policy logs everything (James's "the more we log, the better"): one `decision` JSON line per phase,
  every LLM request and reply, tool calls, briefings, and a snapshot every phase, because the launcher kills the bot
  at game end and an end-of-game summary never gets written.
- Tools: the episode loader (`webdip_episodes.py`); later the HTML game viewer (`game_viewer.py`, needs
  `diplomacy==1.1.2`).

### 6. `eval-design` binding
- **Opponents come from the current field.** For one comparison campaign, keep the same opponent set so results stay
  directly comparable policy to policy. When the field changes, refresh the set and start a new campaign; never pool
  across opponent sets. Use explicit `policy_ref`s; `random` samples the league's champion pool, which can mean
  self-play when we are most of the pool.
- Self-play never decides "better", and hosted XP is not spent on self-play.
- Roster shapes: paired A/B (both candidates plus five field opponents, or candidate seat `slot: -1` with six field
  refs per arm); field eval; health check (one `classic-press-short` episode after any model or soul change, then
  verify every seat's `llm_call` statuses).
- Variant: judge on the league's full variant (`classic-press` for press).
- Country pinning: with the new `countries` config field (section 10b), an A/B can pin each seat's power. One request
  per country permutation, because overrides apply per request.
- Model × soul is the unit under test for LLM policies; the model is fixed per uploaded version.
- Cost: about 15 XP credits per hosted full press game with five LLM seats; LLM spend about $0.006 per seat per
  movement phase (about $0.10 per seat per game) on glm-5.3-flash. The lab set `episode_player_llm_spend_limit_usd`
  to 14. Stream artifacts while games run; do not block on a whole request.

### 7. `diagnosis` binding (James: refine as we go)
Observed failure modes from the lab, first:
- **Silent order drops** (HTTP 200): guarded every phase; 0 seen hosted, but it bites first on convoys and coasts.
- **Re-trusting a betrayer:** 94 returns to trust in 46 relationships over 100 games; 62 of 64 against the liar soul.
- **Map adjacency hallucination:** about 66 wrong guesses per game without a connectivity list, about 21 with it.
- **Untrustworthy commitment ledger:** 10 of 30 sampled "broken promise" verdicts were our own recording errors.
- **Tools skipped unless forced:** 0 `assess_deal` calls until a code gate forced them (17 per game).
- **Pinning a whole plan without comparing it to unconstrained search.**
- **Ignoring the game horizon:** planning a 1905 campaign in a game that ends in 1904 (the new `WEBDIP_END_YEAR` helps).
- **Wake timing:** open wakes hit their time limit 12 of 32 times; the bot was deaf near the deadline.
- **Invisible degradation:** a misconfigured model fails every call and the seat plays its floor with no error.
- **Over-tuning:** more search over the same evaluation hurts; the search exploits a learned evaluation.
Less common or unmeasured: home centers left open, missed builds, overextension, stabbing too early.

### 8. Instruments (`tools/`), ported from the lab
Standard-library Python unless noted; they read files the seed's `fetch-artifacts` downloads, or a local run's output.
- `webdip_episodes.py` (193 lines): the single episode loader (results, replay, seat logs; handles bytes-literal logs).
- `wd_summary.py`: port of `wd.py metrics` and `seats` (per-power score vs field par, coverage, telemetry).
- `paired.py` (42 lines): paired difference and z. `compare.py` (102 lines): A/B by power.
- `wd_costs` (from `wd.py costs`): LLM cost per seat and phase.
- Local runs (need Docker): `wd.py local` (all seats one image) and `wd.py arena` (one candidate vs a local field).
- `llm_sidecar_local.py` (125 lines): local emulator of the hosted LLM sidecar; the only way to run an LLM bot locally
  on its hosted code path. Needs `OPENROUTER_API_KEY`.
- Later: `game_viewer.py` (HTML replay with press; needs `diplomacy`), better tools in general.
- Not ported: `evolve.py`, `value_fit.py` (numpy; the learned evaluation lost), `features.py` (optional).
- Unit tests on small public fixtures from a local episode.

### 9. Reference policy (`players/`): Castlereagh adapted
- **Core: Kissinger search** (pure Python): DumbBot seeds, single/pair/convoy alternatives, coordinate ascent against
  16 sampled opponent plans, a fast adjudicator, the level-1 opponent model, the "competent opponent" test, and the
  convoy approximation (9× faster decisions). Retreats and builds by DumbBot. Keep the golden behavior test (the lab's
  334 recorded decisions) to catch refactor drift.
- **Press layer (optional, modular):** four replaceable parts.
  1. Search service: `search`, `evaluate`, `predict` over a policy dict (stances, trust, expected/required/forbidden
     orders, center values, risk). `press=None` gives behavior identical to gunboat play.
  2. Order floor: the search's legal orders are saved first; the LLM can never leave the seat without legal orders.
  3. Press driver: the single event-driven wake James asked for: on new press, read, reply, re-commit; debounce about
     5 s; up to 20 wakes per phase; generous limits ("set all limits high, then tighten"). Replaces the open,
     negotiate and commit wakes.
  4. Knowledge: a plain `notes(key, text)` store, the raw press log (the current season inline, older seasons through
     a tool), and referee facts derived only from observed orders. Souls and skills are markdown files the user owns.
     The fixed plan, per-power notes and commitment ledger are dropped as defaults.
  The LLM goes only through the hosted sidecar (`COWORLD_LLM_ENDPOINT`); no streaming. Without the endpoint, the
  policy plays its floor. Hand the LLM the map connectivity list, labeled as possible moves.
- **Modes:** one image, `press=off` (default for now) and `press=on`. The first A/B a new user runs (on vs off) is
  then meaningful. A major goal is for press-on to beat press-off before release.
- **Dropped:** the Nim adjudicator (27% faster decisions; the 9× gain was Python), Nash, the learned value function,
  lookahead/rollouts, evolution tooling, and the 15 filler personalities.
- Rejected: Herald (a contract example, not a player); a new heuristic bot.

### 10a. Build tool (`tools/build.sh`)
- Seed contract: `build.sh [--ref <game-ref>] [--tag <image-tag>]`; builds linux/amd64; prints the tag.
- Builds the player base image from a pinned coworld-webdiplomacy commit straight from GitHub (git URL context, `-f
  adapter/Dockerfile.player`; no submodule needed [src: adapter/Dockerfile.player]), then the reference policy on top.
  One stage, pure Python: no Nim, no extra GitHub pulls.
- Works wherever Docker and network exist: local machines and Claude Code cloud. Codex cloud has no documented
  Docker. Without Docker an agent can still edit, analyze, and run tests, but cannot build or upload. The script says
  so clearly instead of failing obscurely.

### 10b. Coworld change (separate PR in this repo)
- Optional `countries` in `EpisodeConfig`: `countries[slot]` is that slot's country (a permutation of 1–7). Set
  through XP `game_config_overrides` with fixed roster slots. Seeds still vary, so episodes still differ. A full
  rotation is one request per permutation.
- `WEBDIP_END_YEAR` passed to bots.
- The hosted coworld must be rebuilt and republished before XP requests can use the new field.

## Validation
Unit tests for ported tools and the golden test for the search; `install.sh` into a scratch dir (no `{{` left; the
manifest lists every binding); `tools/build.sh` builds; one local episode with the built image in each mode; the tools
run on its output; ruff and the tool tests in CI.

## Alternatives considered (rejected, with why)
- Herald as reference: a contract example, not a player.
- A new heuristic bot: pre-empts the user's own first strategy (the seed's `seed-a-policy` owns that).
- Shipping only the press harness: the measured strength is in search.
- Keeping Nim: small speed gain, fragile two-stage build.
- A frozen opponent field forever: results go stale as the field changes. Opponents follow the field; fixed only
  within a campaign.
- Pooled t-test: scores are bounded and bunched near 0, and pooling ignores power.
- Copying the coworld's full docs into the lab: two copies drift. Only linking: fails the self-sufficiency rule.
- pandas/numpy tools: install friction in cloud sessions.
- Building from a local checkout, or pulling the published registry image: the lab lives elsewhere; couples to a
  registry address and release.
