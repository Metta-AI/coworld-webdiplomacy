Design doc · 2026-10-09 · Revised

webDiplomacy optimizer-seed mixin

How we fill the optimizer-seed lab for webDiplomacy so an agent can run the full improvement loop in any environment. Written for James. This revision replaces v1 after review comments and findings from the webdiplomacy_lab.

Executive summary

We adapt the lab's Castlereagh bot as the reference policy. Its core is Kissinger's search, and Castlereagh's press harness sits on top as an optional, modular layer that is off by default for now. The lab's measured evidence drives this choice. In about 100 hosted press games, the press bot scored 0.124–0.126 per seat, while silent Kissinger (the same search with no LLM) scored 0.172–0.176 in the same field, against a parity of 0.143. The strength is in the search. We keep the press layer because policies with press do better than no-press bots in real Diplomacy, and making press-on beat press-off before release is a major goal.

The rest of the work fills the lab completely. Today optimizer/mixin/ (PR #8) is the seed's template with only the identity filled in, so an agent onboarding from Metta-AI/webdip-optimizer sees all five required bindings as gaps and finds no game docs, no reference policy and no build tool. Core seed skills resolve every game-specific fact through the lab's MIXIN.md and the bindings1. We add a lab manual, game docs, the five bindings, instruments ported from the lab, the reference policy and a build tool, plus a small coworld change in a separate PR.

What changed since v1

  • Reference policy. Herald is replaced by an adaptation of Castlereagh: Kissinger search as the core, with the press harness as an optional layer. Press is off by default for now.
  • Evaluation opponents follow the current field. A campaign keeps one opponent set so its results stay comparable, and the set is refreshed when the field changes.
  • Measured priors replace "N floors unknown". Paired seating is the default A/B design, and |z| < 2 counts as no result.
  • Docs. AGENTS.md becomes the lab's operating manual. Game facts move to docs/game.md. docs/protocol.md and docs/platform.md are new. Pinning applies only to coworld-provided docs, and users can write their own long references.
  • Tools. We port the lab's instruments instead of writing new ones, including local-run wrappers and the local LLM sidecar emulator.
  • Diagnosis starts from failures the lab actually observed.
  • Coworld change, separate PR. Optional countries pinning in the episode config and WEBDIP_END_YEAR for bots. This is being implemented now as a PR in coworld-webdiplomacy.

Evidence from the lab

  • Castlereagh's strength is Kissinger's search. The press layer currently costs score.
  • No press change has a verdict yet at 16 games per arm. Two changes trend positive, and one looks harmful.
  • Two search changes have measured gains. Many others were refuted, and more search over the same evaluation hurts.

The headline comparison comes from about 100 hosted press games23. Parity is 1/7 = 0.143 per seat, which is what an average seat scores.

Press-arm resultScore per seatReading
Press bot (Castlereagh)0.124–0.126Below parity of 0.143
Silent Kissinger (same search, no LLM)0.172–0.176Above parity, same field
v7: map-connectivity briefing0.163Trending positive, no verdict at n = 16
Stronger model: deepseek0.192Trending positive, no verdict at n = 16
Stronger model: gpt-6-luna0.175Trending positive, no verdict at n = 16
v8: liar marks0.078Looks harmful

In search, two changes had measured gains4. The "competent opponent" test, which judges opponents by whether their orders are sensible, gained +0.106 (z 2.25). The level-1 opponent model gained +0.135 (z 2.4). Level 0, level 2 and mixes of levels lost 0.10–0.14.

Refuted ideas include learned evaluation (the search exploited it, and score fell from 0.64 to 0.33), rollouts (−0.13), restarts, three-unit attacks, more opponent samples, build search, risk aversion and evolution (53 generations that never beat the champion). The rule the lab drew is that more search over the same evaluation hurts.

Why keep the press harness anyway This is James's call. Policies with press do better than no-press bots in real Diplomacy, so press should help eventually, and Castlereagh is a built-out starting point. Making press-on stronger than press-off before release is a major goal.

Cross-cutting decisions

  • The lab is self-sufficient, and the long references this coworld provides are linked at a pinned commit.
  • Every comparison is country first, against the field average for the same power in the same batch.
  • Tools read files, so they work on local and hosted runs alike. Only hosted results decide anything.
  • The lab supports both webDiplomacy leagues.
Decision 1 · Summaries in the lab, coworld references pinned

The lab carries enough that a newcomer understands the game without leaving it. The long references this repo provides (bot API, replay schema, protocol) are linked at a pinned commit, so they match the coworld version. Users are free to write their own long references in the lab, and nothing restricts that.

Decision 2 · Country first, against same-batch field par

Countries are a seeded shuffle per episode5, and the powers differ a lot. Over 1,238 lab seats, France averaged about 3× what England did3. The metric is therefore a policy's score minus the field average for the same power in the same batch of games.

Decision 3 · Tools read files

A local coworld run-episode writes the same results.json, replay and logs as a hosted episode, so the analysis tools work on both. The analysis tools are standard-library Python. Tools that run games locally need Docker, which exists on local machines and in Claude Code cloud. Codex cloud is unknown. Local results are for debugging only: v4 won the local tournament (+0.093) and then scored below par hosted6.

Decision 4 · Both leagues

The lab supports "webDiplomacy" (league_1bccc63d-cd0a-47d7-92d7-e762797b5f1c, variant classic-press) and "webDiplomacy Gunboat" (league_428e91e5-ee25-4f9c-be5e-a4fc4f993f17, variant classic-gunboat).

1 · Lab manual (AGENTS.md) and manifest (MIXIN.md)

  • AGENTS.md becomes the lab's operating manual. Game facts move to docs/game.md.
  • The manual carries the gotchas an agent must not miss.
  • MIXIN.md fills every binding row with a real summary.

AGENTS.md explains how to use the lab and links every knowledge source: the docs, the five bindings, the tools, the reference policy and META.md. It also holds the loop table. Rules, scoring and structures move out to docs/game.md.

The gotchas it carries:

  • Upstream returns HTTP 200 when it silently drops invalid orders, so diff the saved orders every phase78.
  • Scores are in slot order.
  • The replay's final Finished history entry shows center ownership from before the last autumn, so take final centers from results.json3.
  • Hosted seat logs sometimes arrive as a Python b'...' bytes literal.
  • Use a private HOME per session. Other sessions switch the identity in a shared ~/.softmax/credentials.yaml, and private requests then return 404.
  • Use one image tag per experiment, because rebuilding a tag mid-run switches code.

MIXIN.md lists the league IDs, the five binding rows with real summaries, the meta-recon support rows and the "what else" rows.

Timing

Hosted full classic-press games took 60–100 minutes in the lab, about 61 minutes by one measurement and 80–100 by another. The episode budget cap is 5,910 s, about 98 minutes13. Locally, gunboat games with Ready-marking bots take 40–45 s, and games with search bots take about 4.5 minutes.

3 · The ab binding

  • Metric: score minus same-batch field par for the same power, computed per power and then pooled.
  • Default design is paired seating, with both policies in the same games.
  • |z| < 2 is no result.
  • Tainted games are dropped or flagged before computing means.

Alongside the main metric we report final centers, survival and solo rate. Paired seating needs 2–3× fewer games than separate arms3. Use separate arms only when pairing is impossible.

The z threshold matters in practice. Three +0.08 leads at z ≈ 1.4 vanished on replication4.

Priors for sample size: the per-seat standard deviation is about 0.12–0.18. Resolving a 0.04 difference takes about 150 episodes per arm. At 16 per arm the standard error is 0.02–0.03, which only catches effects of about 0.08 or more. Recompute these after the first batch.

Failing LLM seatEvery call fails and the seat silently plays its floor. Check per-seat llm_call statuses.

Tools: paired.py and compare.py, both ported from the lab.

4 · The survey binding

  • An overview per policy and power, then a short list of games worth opening.
  • One tool, wd_summary.py, ported from the lab.

The overview gives, for each policy and power: games played, score against par, final centers, survival and solo rate, plus the mix of outcomes and reasons.

Games worth opening: our power eliminated early, an opponent solo, our best and worst game per power, a large center swing within one year (a stab or a collapse) and failing LLM seats.

wd_summary.py ports the lab's wd.py metrics and seats commands. seats gives one JSON row per seat, including the supply-center trajectory by year.

5 · The replay-inspection binding

  • Inspection joins the public replay with our own private artifacts on a shared clock of (turn, phase).
  • The reference policy logs everything, every phase.
  • James sees this as a big later improvement. It is fine for now.

The replay is a gzip JSON array of public frames with variant, game, status, history, messages, lifecycle, episode.seed, an optional map PNG and ending14. Our own artifacts are the player log and the private-press ZIP15.

Following James's "the more we log, the better", the reference policy writes one decision JSON line per phase, every LLM request and reply, tool calls, briefings and a snapshot every phase. The per-phase snapshot matters because the launcher kills the bot at game end, so an end-of-game summary never gets written.

Tools: the episode loader webdip_episodes.py now, and later the HTML game viewer game_viewer.py, which needs diplomacy==1.1.2.

6 · The eval-design binding

  • Opponents come from the current field, fixed within one campaign and refreshed when the field changes.
  • Self-play never decides "better", and hosted XP is not spent on it.
  • Judge on the league's full variant. For press, that is classic-press.

Opponents. For one comparison campaign, keep the same opponent set so results stay directly comparable from policy to policy. When the field changes, refresh the set and start a new campaign. Never pool across opponent sets. Use explicit policy_refs, because random samples the league's champion pool, which can mean self-play when our policies are most of the pool.

Roster shapeSeats
Paired A/B (default)Both candidates in the same games, plus five field opponents.
Separate armsPer arm, the candidate at slot: -1 with six field refs. Use it only when pairing is impossible.
Field evalThe candidate against field opponents.
Health checkOne classic-press-short episode after any model or soul change, then verify every seat's llm_call statuses.

Country pinning. With the new countries config field (section 10b), an A/B can pin each seat's power. It takes one request per country permutation, because overrides apply per request.

Unit under test. For LLM policies, the unit under test is the model and soul together. The model is fixed per uploaded version.

Cost. A hosted full press game with five LLM seats costs about 15 XP credits. LLM spend on glm-5.3-flash is about $0.006 per seat per movement phase, or about $0.10 per seat per game. The lab set episode_player_llm_spend_limit_usd to 14. Stream artifacts while games run rather than blocking on a whole request.

9 · Reference policy (players/): Castlereagh adapted

  • The core is Kissinger search in pure Python. It always plays.
  • The press layer is optional and modular, made of four replaceable parts.
  • One image, two modes: press=off (the default for now) and press=on.
  • The Nim adjudicator, Nash, the learned value function and the evolution tooling are dropped.

Core: Kissinger search

The search starts from DumbBot seeds, tries single, pair and convoy alternatives and runs coordinate ascent against 16 sampled opponent plans. It uses a fast adjudicator, the level-1 opponent model, the "competent opponent" test and the convoy approximation, which made decisions 9× faster. Retreats and builds come from DumbBot. We keep the golden behavior test, the lab's 334 recorded decisions, to catch drift during refactors.

Press layer: four replaceable parts

  1. Search service. search, evaluate and predict over a policy dict holding stances, trust, expected, required and forbidden orders, center values and risk. press=None behaves identically to gunboat play.
  2. Order floor. The search's legal orders are saved first, so the LLM can never leave the seat without legal orders.
  3. Press driver. The single event-driven wake James asked for: on new press, read, reply and re-commit. It debounces for about 5 s and allows up to 20 wakes per phase. Limits start generous ("set all limits high, then tighten"). It replaces the open, negotiate and commit wakes.
  4. Knowledge. A plain notes(key, text) store, the raw press log (the current season inline, older seasons through a tool) and referee facts derived only from observed orders. Souls and skills are markdown files the user owns. The fixed plan, per-power notes and commitment ledger are no longer defaults.

The LLM is reached only through the hosted sidecar (COWORLD_LLM_ENDPOINT), without streaming. Without the endpoint, the policy plays its floor. The LLM receives the map connectivity list, labeled as possible moves.

Modes

One image runs in press=off (the default for now) or press=on. This makes the first A/B a new user runs, press on against press off, meaningful. A major goal is for press-on to beat press-off before release.

10a · Build tool (tools/build.sh)

  • Follows the seed contract: build.sh [--ref <game-ref>] [--tag <image-tag>]. It builds linux/amd64 and prints the tag.
  • One stage in pure Python, with no Nim and no extra GitHub pulls.
  • Fails clearly when Docker is missing.

The script builds the player base image from a pinned coworld-webdiplomacy commit straight from GitHub, using a git URL as the build context with -f adapter/Dockerfile.player. No submodule is needed16. It then builds the reference policy on top.

It works wherever Docker and a network exist: local machines and Claude Code cloud. Codex cloud has no documented Docker. Without Docker an agent can still edit, analyze and run tests, but it cannot build or upload. The script says so clearly instead of failing obscurely.

10b · Coworld change (separate PR in this repo)

  • Optional countries in EpisodeConfig, so an experiment can pin each slot's power.
  • WEBDIP_END_YEAR passed to bots.
  • The hosted coworld must be rebuilt and republished before XP requests can use the new field.

countries[slot] is that slot's country, and the list is a permutation of 1–7. It is set through XP game_config_overrides with fixed roster slots. Seeds still vary, so episodes still differ. A full rotation is one request per permutation.

Validation

  • Unit tests for the ported tools, and the golden test for the search.
  • install.sh into a scratch directory leaves no {{ behind, and the manifest lists every binding.
  • tools/build.sh builds. One local episode runs with the built image in each mode, and the tools run on its output.
  • ruff and the tool tests run in CI.
