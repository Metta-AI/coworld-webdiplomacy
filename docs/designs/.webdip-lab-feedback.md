anything yet.** Against the frozen press field, silent Kissinger, which is the same search engine
with no LLM, scores about as well as the best Castlereagh arm and better than Castlereagh v1, the

Wave 1 used the earlier field, without the map, over 100 games. Castlereagh (all arms) scored
0.126 and silent Kissinger 0.174 [doc: `LAB/WORKING_CONTEXT.md`]. No arm has a verdict. Every
stratified comparison is inconclusive at 16 per arm.

**Consequence for the reference policy.** If "adapt Castlereagh" means "ship the press harness as
the strong part", that is not supported. The parts that carry measured strength are:
1. Kissinger search, which is the gunboat champion.
2. The map connectivity list given to the LLM, which is the best-supported press change. It cut
   adjacency mistakes from about 66 to about 21 per game, and v7 is the best of the original
   lineage, though without a verdict.
3. The floor rule: the LLM never sits on the path that produces legal orders.

The LLM harness is a well-instrumented **framework for experiments**, not a proven gain. Present
it that way in the README, and keep a press-off mode (plain Kissinger) as the default comparison
point.

**How a press movement phase works** [doc + code, `press/player.py`]:
1. Save plain Kissinger orders right away, not Ready. This is the floor.
2. "Wakes": each wake is a fresh agent run whose briefing is rebuilt from the journal and the
   workspace. There is an open wake, then negotiate wakes on new press, then a commit wake.
3. Tools: `board`, `connections`, `predict`, `search(policy)`, `evaluate`, `assess_deal`,
   `commit_orders(policy)`, `send_press`, `conversation`, `record_commitment`, `update_plan`,
   `note_power`, `read_skill`.
4. Mark Ready 15 s before the deadline.

Retreats and builds never wake the LLM.

**The policy dict** is the agent's control surface over search:
`stances {POWER: ally|neutral|hostile}`, `trust`, `expected_orders`, `require_orders`,
`forbid_moves_into`, `center_values`, `risk`. Search turns it into constrained seeds, injected
opponent orders, and per-power centre values. In `SearchBot.press`, `None` gives behaviour
bit-identical to gunboat play (golden check, 334/334).

**What carries the strength, and what to drop**:
- **Keep:** SearchBot with level-1 opponents and the "competent" opponent classifier [measured:
  the classifier was worth +0.106 paired, z = 2.25; level 0 lost by 0.135, level 2 by 0.11; see
  `LAB/best_practices.md`]. Also keep the floor-first rule, the saved-orders diff, and the
  connectivity briefing.
- **Drop for a simpler reference:**
  - NashBot, the learned value function (`valuefn.py`, `value_weights.json`; it was exploitable),
    lookahead/rollouts (null), mixed selection, and evolution tooling. All were null or negative.
  - The 15 non-champion personalities, which exist as league fillers.
  - The Nim adjudicator. [guess, partly measured] It only made decisions about 27% faster than the
    pure-Python `fastadj.Adjudicator`, which is still in the file as the reference. The big speedup
    (about 9×) came from the convoy approximation, which is Python. Dropping Nim removes a
    two-stage Docker build that pulls a Nim image and nimpy from GitHub. One change is needed:
    `fastadj.adjudicate` must fall back to the Python class instead of raising when the extension
    is missing. The `diplomacy` package fallback is needed only when convoy approximation is off.
- **Press harness, at its simplest:** one agent, five or six tools, a short soul, no skills
  library. Keep the commitment ledger only if you fix its semantics first (see section 4).
  **Fix the wake model before you copy it.** Today it has open, negotiate and commit wakes. The
  bot cannot hear new press during roughly the last 75 s, and once it has used 4 wakes it runs
  the commit wake early and stays deaf for 2+ minutes. James asked today (on the Castlereagh
  design doc) for a single event-driven wake. On every new press: read it, reply, re-commit.
  Continue until the lock. Configure it with a debounce of about 5 s, up to 20 wakes per phase,
  and generous call limits.

**James's "modular + less opinionated about knowledge structure"** maps onto these seams:
- **Search engine.** Pure Python, behind a `SearchService` with `search / evaluate / predict`.
  This is already a clean seam in `press/search_service.py`.
- **Order floor.** A pluggable "safe default orders" function.
- **Press driver.** The wake loop: event-driven, deadline-aware, and the only part that knows
  phase timing.
- **Knowledge.** The current fixed layout (`plan.md`, one note per power, a journal of
  commitments) is the opinionated part. A less opinionated version gives the agent:
  - a generic `notes(key, text)` / `read_notes()` store;
  - the raw press log (current phase inline in the briefing, older phases through a
    `conversation(power)` tool);
  - optional referee *facts* that come only from observed orders, never from recorded promises.

  Souls and skills are just markdown files the user owns.

**LLM and cost** [measured, `wd.py costs`]:
- Model: `z-ai/glm-5.3-flash`, reasoning effort low.
- Measured cost: about $0.006 per LLM seat per movement phase, about 13–14 calls per seat-phase,
  4.4 s median latency (15.6 s p90). That projects to about $0.10 per seat per full
  `classic-press` game, or $0.70 with all seven seats on LLMs.
- Hosted full games with five LLM seats drew **about 15 XP credits each** (LLM plus compute).
- The model is fixed per uploaded version (the `--llm-model` upload flag).

## 2. Measurement

- **The metric is per-power score against the same-batch field par**, not the pooled mean. Field
  par by power, measured today over 1,238 field seats: France 0.290, Turkey 0.191, Italy 0.119,
  Germany 0.114, Russia 0.114, Austria 0.099, England 0.090. France is about 3× England. Your
  "country first" decision is right. The lab uses
  `wd.py metrics DIR --policy NAME:vN` (par = mean of non-target seats at that power, same
  directories) and `tools/compare.py` (the coworld-ab adapter; groups = all + each power).
- **Per-seat score SD** is about 0.19 in press [doc]. Measured today: 0.09–0.13 for Castlereagh
  arms and 0.08–0.18 for field seats. The lab pre-registered **about 150 episodes per arm** to
  resolve differences of about 0.04. At 16 per arm, SE is 0.02–0.03, which can only catch effects
  of 0.08 or more. **Your N floors can start from these numbers instead of a pilot**: use
  SD ≈ 0.12–0.18 per seat and par spreads above, and recompute after the first batch.
- **Paired designs** (both policies seated in the same games) beat separate arms by 2–3× in games
  needed [doc, measured in gunboat]. Rule from repeated replication failures: treat **|z| < 2 as
  no result**. Three "+0.08 at z ≈ 1.4" leads shrank to zero when re-run (`LAB/best_practices.md`).
- **Judge against the field the policy will meet.** The same bot ranked first or last depending
  on the opponents [measured]. Kissinger scored 0.38 against DumbBots and won against search
  fields.
- **Countries and seeds.** The lab never pinned countries. Every seat is `slot: -1`, each episode
  gets a fresh seed, and analysis stratifies by power. For LLM seats, a matched seed would not
  give matched games anyway, because the models are not deterministic. [guess]
- **What counted as tainted** (dropped or flagged before means):
  - a nonzero `rejected` count in our `decision` log (upstream silently dropped an order);
  - any `exception` event in our seat log;
  - an episode whose artifacts were not all downloaded (report coverage, never impute);
  - a "failing LLM seat", meaning a model/parameter mismatch makes every call fail and the seat
    silently plays the floor. Check `llm_call` statuses per seat;
  - a wrong field cohort (the pre-geometry and geometry fields are never pooled).

  We saw no cancelled or timed-out press-ab1 games: 208/208 ended `drawn`/`won` at the end year
  [measured]. Note that `reason` lives in `results.json` and is easy to skip.
- **Final centres** come from `results.json` `members[].supplyCenterNo` (a string). The replay's
  `Finished` history entry shows ownership *before* the final autumn and is wrong for the last
  year [doc, verified repeatedly in the diagnosis notes].

## 3. Evaluation practice

- **Hosted XP requests are the instrument.** Each request has one candidate seat
  (`policy_ref`, `slot -1`) and six explicit field `policy_ref`s.
  - Builder: `LAB/experiments/press-ab1/make_request.py`.
  - Runner: `run_waves.sh`.
  - Field ids are frozen there; the field is also the press league's filler roster.
  - Use **explicit refs, never `random`**. `random` samples the league champion pool, which was
    only us, so it would produce self-play.
- **Variant:** `classic-press`, because the full game decides. `classic-press-short` was used only
  for health and activation checks after any model or soul change: one episode, then verify every
  seat's `llm_call` statuses.
- **Durations and cost** [measured]: a full hosted `classic-press` game took about **61 minutes**
  from start to finish. Sixteen ran in parallel per request, so a 16-game arm takes about 1 hour of
  wall clock. Cost was about 15 XP credits per game. We set
  `episode_player_llm_spend_limit_usd: 14` per episode, which is split over seven seats.
- **Local runs:**
  - `wd.py local` (all seats one image) and `wd.py arena` (slot 0 candidate vs a local field).
    Local gunboat games take about 45 s.
  - Press needs `tools/llm_sidecar_local.py`, a host emulator of the sidecar contract that rejects
    streaming and strips the same fields. It needs an OpenRouter key and must run outside the
    command sandbox, or inbound connections never arrive.
  - Local self-play is used only for debugging and activation checks, never for verdicts.
- **What went wrong:**
  - **Shared credentials.** Other sessions running `coworld player use` silently switched the
    identity in `~/.softmax/credentials.yaml`. Private requests then returned 404, and episodes
    listed as "unavailable". Fix: a private `HOME` copy per session (`LAB/AGENTS.md`, "Identity
    hygiene").
  - Hosted artifact downloads were sometimes missing on the first fetch (rate limits). Re-running
    the fetcher resumes.
  - Seat logs sometimes arrive as a Python `b'...'` bytes literal.
  - A parent request rolls up to `failed` as soon as one child fails; wait for every child.
  - Rebuilding an image tag mid-run silently switched later local games to the new code. Use one
    tag per experiment.
  - Killing a local arena leaks game and player containers.
  - Map PNGs in replays fill the disk (`wd.py slim`).
  - Per-model sidecar quirks: see section 4.

## 4. Failure modes actually observed (versus your section 7 list)

| Your item | Observed? |
| --- | --- |
| Silent seat / orders dropped (HTTP 200) | Real risk and guarded every phase. We saw 0 rejections in hosted press-ab1 games [doc]. Early convoy/coast handling is where it bites [guess]. Keep it first in triage. |
| Not marking Ready | Matters for wall clock only. Our bots Ready 15 s before the deadline; LLM seats rarely all Ready, so press games run about the full 4 minutes per phase. |
| Home centre left open / builds / overextension | Not separately measured. Search covers the tactics; I would not lead with these. |
| Stabbed by a partner | **Yes, and the real failure is re-trusting.** After a first breach or trusted attack, we returned to trusting the same power 94 times in 46 relationships over 100 games (62 of 64 for the liar soul) [measured, `LAB/TENTATIVE_LESSONS.md`]. Verbal reassurance restored trust before any demonstrated compliance. |
| Stabbing too early | Not observed. |
| Press that contradicts our orders | Seen indirectly: commitments recorded wrongly (next row). |
| LLM timeout / 429 with no fallback | The floor design made this harmless for score. The real hazard is **invisible degradation**: a misconfigured model fails every call and the seat plays Kissinger with no error. |
| Deadline miss | Never with the floor design. |

**Missing from your list (all observed):**
1. **Adjacency hallucination.** Without a connectivity list, the LLM reasoned about the map from
   memory and got it wrong about 66 times per game (for example, claiming SER/BUL/GRE were not
   connected). With the list it was about 21. Hand every LLM the map.
2. **Untrustworthy commitment ledger.** 10 of 30 sampled "broken" verdicts were *our own*
   recording errors: reversed DMZs, invented holds, the wrong season. The verifier also counts a
   *failed attempted* move as "entered". Do not build trust automation on recorded promises; use
   observed orders against our units and centres.
3. **Tools skipped unless forced.** v1 made 0 `assess_deal` calls in a game; a code gate (v3)
   raised it to 17. A cost warning with an override (v5) was overridden both times it fired.
4. **Pinning a whole tactical plan** through `require_orders` without comparing it to
   unconstrained search. This was the top diagnosis item (`LAB/evidence/press-ab1/notes/DIAGNOSIS.md`
   §5).
5. **Ignoring the game horizon.** The bot negotiated "1905 offensives" in a game that ends in
   1904, and kept positional value in the final autumn, when only owned centres score.
6. **Wake timing.** v1's open wake hit its time limit 12 of 32 times. The bot is deaf near the
   deadline (section 1). Late replies appear in the private archive but never reached a wake.
7. **Model/sidecar parameter mismatches**, which turn a seat into a silent floor (verified hosted):
   - The sidecar forces `provider.require_parameters=true`.
   - gpt-6-luna and claude-haiku-5.5 reject `temperature`.
   - gemini-3.5-flash-lite rejects reasoning off.
   - deepseek, qwen and minimax reason past a 2,000-token `max_tokens` and return nothing.
   - qwen drew about 40 provider 429s per game; minimax managed about 1 call per 60 s wake.

   Details: `LAB/docs/webdiplomacy-gameplay.md`, "LLM players".
8. **More search over the same evaluation hurts.** Three restarts, triples, 24 samples and
   rollouts were all null or negative; the learned evaluation was exploited. This matters for any
   user who will tune the reference policy.

## 6. What is wrong or missing in the plan

1. **Herald as the reference policy.** James already flagged this. The adaptation should start
   from Kissinger search plus an *optional* press layer, not from the press layer alone (see the
   headline). Seed it as two personalities in one image (`press=off|on`) so the first A/B a new
   user runs is meaningful.
2. **N floors "not known yet".** They are known roughly (section 2). Put them in the binding as
   priors instead of "directional only".
3. **Field definition is missing.** A/B arms with "identical pinned rosters (policy_ref in all
   seven slots)" means self-play if the user has only their own policy. The plan needs a **frozen
   reference field**: the league's filler roster, or published field versions. Without one there
   is nothing to evaluate against. The press field ids are in `make_request.py`, and the gunboat
   fillers are listed in `LAB/WORKING_CONTEXT.md`.
4. **Paired seating is absent.** Add "seat both policies in the same games" as the default A/B
   design. It is cheaper than country pinning and gives most of the same benefit.
5. **Taint list** should add: failing-LLM-seat detection, a nonzero `rejected` count, and partial
   artifact coverage. "Silent seat" is hard to detect from results alone; it needs the seat log.
6. **The "Finished" replay entry gotcha** belongs in game.md and the replay binding. Otherwise
   every new timeline tool reports wrong final centres.
7. **Wall clock.** Your 88-minute worst case is an estimate. Measured hosted full press games take
   about 61 minutes. Cloud agents need to stream artifacts while games run (the seed's streaming
   pipeline), not block on a request.
8. **Cloud sessions and the build.**
   - `tools/build.sh` will need Docker and network wherever it runs. A Nim builder stage would make
     that worse, which is another reason to drop Nim.
   - LLM bots cannot be run locally in the cloud without an OpenRouter key and a sidecar
     emulator. Say so, and make the reference policy fall back to its floor when
     `COWORLD_LLM_ENDPOINT` is unset, as Castlereagh does.
9. **Credential sharing.** Any environment where several agents share one `~/.softmax` will hit
   the identity-switch 404s. Put the private-`HOME` recipe in the mixin's AGENTS.md.
10. **Strategy doc.** General Diplomacy openings are fine. But tell users the measured field facts:
    France about 3× England, and that the best press seat in our field is a *liar* on gpt-6-luna.
11. **Model choice is per uploaded version.** Changing the model means a new upload. The
    eval-design binding should treat model × soul as the unit under test. Our rotation arms showed
    model swaps moving the mean by about 0.04, which is within noise at n = 16.

## 7. Pinning countries in XP requests

**No direct mechanism exists today** [verified in your repo at `f6bb21c`]:
- `adapter/episode.py:83-85` does `countries = list(range(1, 8))` followed by
  `random.Random(config.seed).shuffle(countries)`.
- `EpisodeConfig` (`adapter/config.py`) has no country field, and its `extra="forbid"` rejects
  unknown keys.

**Workaround available now** [source-verified for the platform; not tried by this lab]:
1. The platform's `game_config_overrides.seed` (an explicit integer) pins **every** episode in a
   request to that seed [doc: `player_labs/docs/platform-reference.md`, "XP composition"].
2. Give the roster **fixed integer slots** instead of `slot: -1`.
3. Precompute offline which seed puts the desired country on slot 0:
   `random.Random(s).shuffle(list(range(1, 8)))`, which is deterministic for a given int seed.
4. Run one request per desired country (or per country × seed).

Caveats:
- Every episode in that request repeats the same seed, so deterministic bots replay identical
  games. That is useful only with LLM seats or for repeat-noise checks. For deterministic
  policies, use several requests with different seeds that map to the same country.
- `WEBDIP_SEED` (episode seed × 7 + slot) also changes with the seed, so the bots' own RNG
  changes too.
- Check that fixed integer slots are honoured in XP rosters before relying on it [guess: the
  platform reference says open seats rotate, which implies explicit slots are fixed].

**Proper fix (small adapter change)** [guess at the design]:
- Add `countries: list[int] | None = None` to `EpisodeConfig`, validated as a permutation of 1–7.
  When it is set, skip the shuffle.
- A request with fixed slots and `game_config_overrides.countries` then pins each seat's power.
  The seed stays free, so episodes still differ.
- A full rotation is seven requests, one per country permutation, unless the platform gains
  per-episode overrides.
- `results.json` already records `countries`, so the analysis tools need no change.
- Also add an optional `country_rotation: int` (offset by episode index) only if the adapter can
  learn the episode index. Today it cannot, as far as I can see.
